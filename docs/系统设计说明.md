# 系统设计说明

> 本文档为系统的纯描述性说明，覆盖模块划分、功能细节与实现逻辑、数据结构、交互流程及界面布局。
> 文档不含任何代码片段或伪代码，仅描述系统"做什么"与"如何组织"。对应源码位于 `iframe/` 目录。
> 出厂数据基线为 **1.0**，首次激活入口为「从源码导入」（自动解析源码文件写入数据库）。

---

## 一、子系统定位与目标

本子系统解决的核心问题是：原本驱动 AI 的提示词、EDA 函数描述、自定义工具实现、资源等核心数据，以硬编码 JavaScript 常量的形式存在，难以检索、编辑与版本化。

子系统将其改造为"可本地持久化、可在线编辑、可图形化浏览"的数据集合，并通过关系图谱呈现数据之间的引用网络。设计遵循两条基本原则：

1. **零成本兼容原有运行方式**：默认不激活本地数据库，扩展直接运行于内置 JavaScript 常量之上；仅当用户主动"导入 → 从源码导入"后，数据才写入本地数据库，且后续启动自动以数据库为准。
2. **数据、视图、交互三层解耦**：本地数据层（读写与派生）、抽屉视图（浏览与编辑）、图谱视图（可视化）相互独立，通过统一的数据接口与事件机制协作。

---

## 二、模块划分

子系统由三个核心模块与两个第三方库构成。此外，主控制器所依赖的「取消信号管理」与「错误分类」两个通用模块不属于本子系统，其说明见《AI执行框架设计说明（ai_mindmap.md）》。

### 2.1 本地数据层（data-store.js）

负责全部数据的持久化与派生计算，是整个子系统的唯一数据真相源。对外暴露一个统一的数据服务对象，被抽屉视图、图谱视图与主控制器共享。

主要职责包括：

- 捕获出厂默认数据快照。
- 在本地 IndexedDB 数据库中读写业务数据（底层由 AlaSQL 提供 SQL 能力）。
- 导入、导出、删除与恢复默认数据。
- 运行时缓存刷新，包括函数体重建与 system 消息即时生效。
- 引用检测、引用标记还原、图谱数据派生与调用日志存储。

### 2.2 数据管理抽屉（editor-drawer.js）

负责数据的浏览、搜索、编辑与导入导出交互。它本身不持有数据，所有读写均委托给本地数据层。

主要职责包括：

- 渲染状态徽标（已激活 / 未激活）。
- 提供六个分栏的内容切换（顺序：图谱 / 提示词 / 精选工具 / EDA函数 / 资源 / 日志），日志分栏按激活状态动态显隐。
- 列表搜索与分页。
- 可拖拽分隔条调节列表与编辑区宽度。
- 编辑表单的校验与保存。
- `@引用` 标记的渲染、高亮与跳转。
- 删除前的引用保护与二次确认。
- 通过 AI 根据函数实现反推描述与参数结构。

该模块对外暴露跳转接口，供图谱视图在右键"编辑"或双击节点时联动定位到对应条目。

### 2.3 关系图谱视图（graph-view.js）

负责把数据层派生的引用关系以图形方式呈现。基于 D3 力导向布局，独立于抽屉的其他分栏，仅在"图谱"分栏激活时渲染。

主要职责包括：

- 节点与引用连线的力导向布局渲染。
- 按类型着色与图例过滤。
- 搜索链路高亮、缩放平移、拖拽与钉住。
- 节点选中态的跨分栏保留。
- 右键增删改查菜单与导出图片。

### 2.4 第三方库（vendor 目录）

- AlaSQL：本地 SQL 引擎，提供 IndexedDB 存储能力，随扩展离线打包。
- D3：力导向布局与选择集库，随扩展离线打包，无外网依赖。

## 三、数据结构

### 3.1 业务数据主表

本地数据库按数据类型划分为多张主表，核心四类业务数据各自的字段结构如下：

本地数据库名为 `ProSchematicAiDB`，由 AlaSQL 的 INDEXEDDB 引擎管理，共六张表：四张业务表与两张日志表。业务表在 AlaSQL 中不声明列类型，字段由写入的行对象隐式决定。

**提示词（prompts）**

- 名称（主键，同时作为引用锚点）
- 描述
- 消息数组（以 JSON 字符串存储原始 `messages` 结构）
- 分类标签（由名称前缀自动归类为 index / domain / knowledge / execution）
- 是否被用户修改过
- 更新时间

**工具（tools）**

三类工具合存一张表，由来源字段区分，不存在独立的"EDA 函数表"：

- 名称（主键，同时作为引用锚点）
- 描述
- 参数 JSON Schema（以 JSON 字符串存储）
- 函数实现源码（仅元工具与精选工具具备；EDA 原生 API 的实现位于宿主内部，前端无源码，此字段为空）
- 来源（`jdb` 原生 API / `mcp` 元工具 / `custom` 精选工具）
- 是否启用
- 是否被用户修改过
- 更新时间

**资源（resources）**

出厂默认集由独立文件 `mcp/resources.js` 定义 `window.resourceList`（内置海量嘉立创原理图 EDA 开发资料，按主题域铺开，根索引 `resource_jlc_sch_overview` 作导航入口，资料正文以 `@uri` 互链）；`data-store.js` 经 `factoryDefaults.resourceList` + `buildFactoryResourceRows()` 将其转成数据库行，与提示词/工具完全对称。资源行字段包括：

- URI（主键，提示词以 `@uri` 引用）
- 资源名
- 描述
- MIME 类型
- 资源内容（可编辑的 prompt-like 结构化正文）
- 是否修改标记（is_modified，导入合并时据此判定覆盖策略）
- 更新时间

**元信息（meta）**

键值两列，固定记录当前种子版本与出厂版本两行。代码中仅存在出厂版本常量，种子版本是从该表读出的运行时值，随导入的数据文件版本变化。

### 3.2 引用关系的逻辑结构

系统并不单独存储一张"引用表"，而是在需要时从主表实时派生引用关系。

引用锚点的书写形式为 `@名称`，即在被引用对象的名称前加 `@` 前缀。解析器只承认带 `@` 前缀的显式标记，对未加前缀的裸名称不做子串猜测，从而杜绝"前缀同名"造成的误报。

引用的抽取来源分为两类：

1. **工具实现内部的互调**：自定义工具的函数实现代码中调用了其他工具。可识别三类真实调用：`window.curatedTools.<name>(...)` / `window.mcpProtocol.<name>(...)` 形式的全局对象调用（构成强引用 `tool_call`），以及 `eda.<完整路径>` 形式的原生 API 调用（构成弱引用 `native_fallback`）。全局对象调用只取第一级方法名（切断 `.find` 等链式后缀），避免把 `curatedToolSchemas.find` 误判为被调用工具。抽取前先剥离注释与字符串字面量，避免把示例文本误判为真实调用。该识别与编辑器对真实调用的高亮同源，保证图谱边与代码高亮一致。
2. **提示词内的引用**：提示词的描述与消息正文中书写了其他条目名称作为引用。提示词文本不做注释剥离。

引用分为强引用与弱引用两类：

- 强引用：提示词引用提示词、提示词引用工具、工具调用工具。
- 弱引用：原生 API 兜底调用、提示词内的调用范例字面量。

系统特别避免生成"自引用环边"（即来源与目标为同一节点的连线），因为这类边不提供额外信息且会在渲染时形成无意义弧线。数据派生阶段与图谱渲染阶段各过滤一次，形成双保险。

提示词引用提示词，如流程提示互引 `domain_*`、`knowledge_*`、`execution_*`、`execution_guidance`、`prompt_tool`（提示词引用工具，「推荐工具：@xxx」「规则：…调用 @knowledge_spacing 获取精确数值」等），这些标记在导入后即可被解析并在图谱中渲染出提示词侧连线；工具实现内部的互调与原生 API 调用则构成其余引用来源。

### 3.3 调用日志结构

数据库激活后，每次与 AI 的交互都会生成一条日志记录，分两阶段写入：

- **请求阶段**：写入请求负载，并同时保存当时使用的提示词快照与工具快照。
- **响应阶段**：响应返回后回填响应负载。

日志由两张表承载：

- **会话表（chat_sessions）**：会话标识、标题、创建时间、更新时间。
- **轮次日志表（chat_logs）**：日志标识、所属会话、轮次序号、请求负载、响应负载、提示词快照、工具快照、创建时间。

日志按"会话"与"轮次"两级组织，会话按创建时间倒序列出，轮次在会话内按序号正序排列。日志为只读快照，不参与导入、导出、恢复默认等数据维护操作；但"删除数据库"会连同日志一起清除。

日志的持久化采用"发射后不管"的方式，不阻塞对话主流程；写入失败仅在控制台告警，不影响正在进行的会话。

### 3.4 数据版本标记

导出数据时携带版本号，形成形如 `psa-export.v{版本号}.json` 的数据文件，用于在其他环境中导入并保持版本可追溯。导出内容为业务三表的完整行结构（含修改标记、更新时间与函数实现源码），其中工具按 `source` 字段（jdb/mcp/custom）分组为三个子数组，重新导入后可正确还原所有工具分类；日志两表不在其中。

## 四、功能细节与实现逻辑

### 4.1 两种数据模式

子系统存在两种互斥的运行模式：

- **未激活模式（默认）**：扩展直接读取内置 JavaScript 常量。此时抽屉为只读预览，用户可查看数据但不可编辑。
- **已激活模式**：用户点击"导入"并选择"从源码导入"（首次激活起点，读取由 mcp/prompts.js / eda-api.js / mcp/meta-tools.js / mcp/curated-tools/index.js / mcp/resources.js 加载到运行时内存中的常量并写入数据库）后，数据被写入本地数据库。此后每次启动自动以数据库为准，抽屉可编辑。

启动时的模式判定优先查询浏览器的数据库清单，判断目标库是否存在；该能力不可用时回退到本地存储中的激活标记。若库存在但提示词表与工具表均为空，视为异常残留，仍按未激活处理。任一环节出错都会安全降级为未激活，保证扩展始终能按原始 JavaScript 数据运行。

### 4.2 导入与合并策略

导入有两个来源：

- **从源码导入**（首次激活起点）：直接读取运行时内存中的 `window.promptList` / `window.edaApi` / `window.mcpProtocol` / `window.curatedTools` 常量写入数据库，无需选择文件。
- **从本地文件导入**：选择 `psa-export.v*.json` 文件，仅支持 JSON 格式。JSON 会严格校验版本字段与业务表结构，不合法则拒绝导入。导入时兼容旧版扁平 `tools` 数组格式与新版按 `source`（jdb/mcp/custom）分组的对象格式。

首次导入直接整体写入。在已激活状态下再次导入时，采用"用户修改优先"的合并策略：

- 对于用户已修改过的条目，导入过程保留用户的修改，不被覆盖。
- 对于用户未修改过的条目，导入的新数据会覆写旧数据。
- 对于用户已修改、但新数据中已不存在的条目，予以保留。
- 对于用户未修改、且新数据中已不存在的条目，随之删除。

这种策略保证了版本升级时既可获得新内容，又不丢失用户自定义成果。

### 4.2.1 写入策略

所有读取均直接命中内存缓存，不查库。写入则先更新内存缓存，再以"整表覆写"的方式落盘——删除原表、重建、批量插入。这一保守组合规避了 AlaSQL 的 IndexedDB 引擎在逐行更新与删除上的兼容性风险，在千行量级下开销可以忽略。

### 4.3 即时生效机制

编辑保存后，部分数据会立即影响正在运行的会话：

- 工具的函数实现代码在保存前经过语法校验，保存后热重建并挂回运行时对象，使后续对话能调用到新实现。重建失败时回退到出厂实现并在控制台告警，不会让运行时失去该工具。
- system 消息的修改会即时替换当前会话中的 system 消息，无需重启对话。替换前会先还原引用标记，因此送入模型的仍是裸名称文本。

运行时缓存刷新会重建并覆盖全部 `window.*` 运行时对象——包括提示词列表（`promptList`）、三类工具描述（`edaApi` / `mcpProtocol.metaToolSchemas` / `curatedTools.curatedToolSchemas`）、资源列表（`resourceList`）、携带实现代码的工具经 `new Function` 重建的函数体，以及 system 消息。刷新始终赋新的数组与对象，绝不原地修改，以保证出厂快照不被污染。工具栏搜索、提示词森林 `@uri` 引用解析与节点引用高亮均实时消费这些 `window.*` 缓存，不另建独立的索引表，因此任何一次刷新都会同步反映到搜索与引用查找结果。

### 4.4 引用检测与删除保护

删除提示词或自定义工具前，系统会统一扫描两类引用来源，列出所有引用方。若发现仍存在引用，会弹出引用者清单并要求用户二次确认；确认后仍可强制删除，系统不强制要求先把引用清零。这一取舍在防止误删与避免死锁之间取得平衡——若强制清零，循环引用将导致任何一方都无法删除。

### 4.5 `@引用` 标记与还原

编辑区在正文中将引用渲染为可交互的高亮标记：

- 单击标记展开信息卡，展示目标类型、描述、启用状态；若目标不存在则标红警示。
- 双击标记跳转到对应条目。
- 文本送入 AI 模型之前，系统会统一将 `@name` 标记还原为裸名称，确保模型看到的内容与标记化之前完全一致（还原统一采用无花括号的 `@name` 形式，与 `stripRefMarks` 一致）。

对于函数实现与提示词正文中显式的 `@名称` 引用，编辑区在**显示态**以只读高亮预览区呈现，具有相同的高亮、单击信息卡与双击跳转行为；编辑态展示可编辑表单与保存/取消按钮（编辑态与显示态互斥，不并存）。

### 4.6 图谱数据派生

图谱视图所需的数据由本地数据层实时派生：

- 节点类型分为提示词、精选工具、MCP 元工具、EDA 原生 API、资源（EDA 开发资料，紫色）五类，节点半径按出入度缩放；EDA 原生 API 与资源资料默认折叠（图例可展开，被提示词 @uri 引用时随连线出现），避免海量节点淹没图谱。
- 连线类型共五种：提示词引用提示词、提示词引用工具（目标可为函数或资源）、工具调用工具三者为强引用，原生 API 降级调用与提示词内的调用范例为弱引用。强弱以线条粗细表达，类型以颜色区分。
- "描述-实现配对"关系不生成连线。该关系的来源与目标必然是同一节点，会被渲染成节点旁带箭头的弧线，构成纯视觉噪音；其信息改由节点半径与悬停提示中的出入度体现。
- 派生过程主动排除自环边，渲染层再做一次过滤作为双保险。

### 4.7 调用日志写入与回填

数据库激活后，主控制器在每次调用 AI 前写入请求快照，响应返回后回填响应快照。日志分栏按会话与轮次展示，会话详情头部显示轮次数与累计 token 消耗（逐轮累加响应快照 `usage.total_tokens`）；轮次可展开查看，可经轮次标题栏的「复制」按钮复制该轮完整 JSON，或经头部「复制全部」按钮一键复制该会话全部轮次的请求/响应 JSON。

"清空日志"操作仅清空两张日志表，不影响任何业务数据；该入口位于日志分栏的列表工具栏，而非顶部全局状态区。

### 4.8 AI 辅助编辑函数

用户在编辑工具实现代码后，可触发"AI 格式化并补全(代码+描述)"。系统复用对话已配置的 AI 通道，对用户编写的函数依次完成格式化、修复明显缺陷、补充函数内中文注释，并重新生成工具描述与参数结构，统一回填到编辑表单。生成期间按钮置为不可用并显示进行中状态。回填只写入表单，不自动保存，需用户复核后手动保存。

该按钮仅在具备函数实现的工具上出现，EDA 原生 API 条目没有此入口。

## 五、交互流程

### 5.1 激活本地数据库流程

1. 用户打开数据管理抽屉。
2. 在只读预览态下点击"导入"，在询问框中选择"从源码导入"（此时本地尚无任何导出文件，只能以源码为数据源）。
3. 系统读取运行时内存中的源码常量，构建业务行写入本地数据库并激活，全程无需文件选择。
4. 抽屉切换为可编辑态，日志分栏随之出现，后续启动自动以数据库为准。

### 5.2 编辑与即时生效流程

1. 用户在某一分栏选中条目。
2. 编辑区加载该条目字段。
3. 用户修改描述、参数结构或函数实现。
4. 保存时执行对应校验（JSON 校验 / 语法校验）。
5. 校验通过后写回数据库，并触发即时生效逻辑。

### 5.3 删除与引用保护流程

1. 用户发起删除。
2. 系统检测该条目是否仍被引用。
3. 若无引用，二次确认后直接删除。
4. 若有引用，弹出引用者清单说明删除可能导致其失效，用户确认后仍可强制删除。

删除入口的可见范围有差别：提示词分栏的编辑区始终提供删除；精选工具分栏仅对用户自建或已修改的自定义工具提供删除；EDA 函数分栏不提供删除（只能禁用）；资源分栏默认不提供删除（资源更新经导入 `psa-export.v*.json` 的 resources 项覆盖），但提供「恢复此条默认」按钮（与提示词/工具分栏对称，调用 `dataStore.resetResource(uri)` 从出厂快照单条还原）。

### 5.4 图谱浏览流程

1. 用户切换到"图谱"分栏。
2. 图谱视图从数据层派生节点与连线并渲染。
3. 用户可拖拽节点、缩放平移画布、点击图例过滤类型。
4. 搜索时高亮相关引用链路。
5. 右键节点或连线执行增删改查。
6. 选中节点后切换分栏再切回，选中态仍然保留。

### 5.5 日志回溯流程

1. 数据库激活后产生对话。
2. 每次对话轮次生成请求与响应日志，时间戳按本地系统时间记录（无 UTC 偏移）。
3. 用户在"日志"分栏按会话展开，定位到某一轮。
4. 每轮整体可折叠（外层折叠容器**默认折叠**），点击轮次标题展开。展开后请求与响应各自以标签直接呈现，**不再各自整体折叠**；其 JSON 内容按 `{ }` `[ ]` 的真实层级递归拆分为可折叠单元，每个对象与数组**默认展开**，仅在左括号前显示折叠箭头，不显示键名与数量等统计文字。复制经轮次标题栏右侧的「复制」按钮触发，将该轮完整请求与响应 JSON 写入剪贴板；会话详情头部另有「复制全部」按钮，一键复制该会话全部轮次的请求/响应 JSON，并展示累计 token 消耗总量（逐轮累加响应快照 `usage.total_tokens`）。

## 六、界面布局

### 6.1 整体布局

数据管理抽屉以浮层形式出现在对话界面中，通过右上角"数据"按钮开启。抽屉内部采用"顶部状态区 + 分栏标签 + 列表与编辑双栏"的结构。

### 6.2 状态区

顶部展示数据库激活状态徽标，已激活时显示当前数据版本，未激活时标注为原始 JS 只读预览。状态区右侧并排提供三个高频必要操作入口（不分区）：`导入`、`导出`、`删除数据库`，以及关闭按钮。原「导入默认1.0 / 导入文件 / 导出JSON / 导出默认JS / 恢复全部默认」五个拆分或冗余按钮已精简合并。

- **导入**：点击弹出自定义询问框，含「从源码导入」「从本地文件导入」「取消」三个并列选项，需明确选择其一，关闭询问框不执行任何导入。「从源码导入」直接读取运行时内存中的源码常量（源码文件已在页面加载时由宿主执行），不再弹文件选择框；「从本地文件导入」才弹出文件选择框，仅接受 .json 文件。
- **导出**：点击输入一次版本号，产出**单个** `psa-export.v{版本}.json`（提示词/业务数据，工具按 jdb/mcp/custom 分组）。函数实现源码以 `impl_code` 字段内嵌于该 JSON 中，导入时自动重建，因此单文件即可完成完整还原，与「从本地文件导入」形成对称闭环。
- **删除数据库**：危险操作，删除库即回退原始 JS（即恢复默认状态）；因与「恢复全部默认」语义重合，后者已移除。

### 6.3 六个分栏

分栏标签按下列顺序自左向右排列（与 `editor-drawer.js` 的 `TABS` 常量严格一致），标签上带有条目计数：

1. **图谱**：关系图谱可视化，位于最左侧，标签不带计数。
2. **提示词**：含 prompt_index（极简索引），其余按 domain/knowledge/execution 分类，支持新增与删除自定义提示词。抽屉打开时默认停留在此分栏。
3. **精选工具**：精选自定义工具与 MCP 元工具合并展示。
4. **EDA函数**：原生 API 描述浏览与编辑。
5. **资源**：资源查看与编辑（显示态 @引用高亮 + 编辑态表单保存，与提示词分栏对称）。
6. **日志**：调用快照。未激活时该分栏整体隐藏，且若当前正停留其上会自动回退到提示词分栏。

### 6.4 列表与编辑双栏

在业务数据分栏中，左侧为带搜索与分页的列表，右侧为编辑区。两者之间是可拖拽的分隔条，用户可实时调节左右宽度比例；该比例不做持久化，重新打开抽屉恢复默认布局。

列表顶部工具栏包含搜索框与分页控件。搜索按名称与描述同时匹配且忽略大小写，输入即过滤并回到首页；分页每页 50 条。搜索框在日志与图谱两个分栏隐藏，后者自带独立搜索框。"新增"按钮仅在提示词与精选工具两个分栏、且数据库已激活时出现；"清空日志"按钮仅在日志分栏出现。

列表条目显示名称与描述，并以红点标记用户已修改过的条目，以文字标记已禁用的工具。

编辑区以 `editMode` 区分两种互斥状态，二者不并存：
- **显示态**（默认，只读）：条目元信息、只读高亮预览（描述/内容/参数模式/函数实现，`@引用` 高亮预览区即在此呈现）、引用信息区（列出该条目调用谁、被谁引用），以及「编辑」「恢复此条默认」「删除」等操作按钮。
- **编辑态**（点「编辑」进入）：条目元信息、可编辑字段表单、校验提示、引用信息区，以及「保存」「取消」按钮（工具类另含「AI 格式化并补全(代码+描述)」）；编辑态不再重复展示 `@引用` 只读预览区。保存成功或切换条目后自动回到显示态。

未激活时强制显示态，全部预览只读，且「编辑」按钮禁用并显示只读横幅，引导用户先行激活。

各分栏的字段有所不同：提示词提供描述与内容两项，内容区在单条纯文本消息时直接编辑正文、其余情况编辑完整消息 JSON；工具提供描述、参数模式与函数实现三项，并附启用开关，其中函数实现与"AI 格式化并补全(代码+描述)"按钮仅对非原生 API 条目出现。参数模式与消息 JSON 在保存前强制校验，非法时拒绝保存并提示。

### 6.5 图谱视图布局

图谱分栏内包含：

- 顶部工具栏，含独立搜索框与"适应画布""重置布局"两个按钮。
- 图例，列出五类节点色板，点击可切换对应类型的显示与隐藏。
- 主画布区域，渲染力导向节点与连线。节点按类型着色，连线按引用类型着色并配有逐类型箭头，弱引用以虚线区分。
- 悬浮提示框，展示节点或连线详情。
- 右键上下文菜单，分节点、连线、空白三类。

三类右键菜单的条目分别为：

- **节点**：编辑、复制 name、钉住或解钉、以此为中心聚焦、删除。
- **连线**：查看引用上下文、解除引用并定位编辑，以及强弱切换项——该项仅作提示，引用强弱由内容语法自动判定，不支持手动改写。
- **空白**：新建提示词、新建函数、适应画布、重置布局、导出图谱 PNG。

菜单项以按下事件触发并阻止冒泡，避免被画布的缩放与点击监听抢先关闭。

单击节点将其标记为选中并以品红（`#ff1493`）描边高亮，选中态跨重绘持久，切换分栏后返回仍然保留。搜索命中后沿出入边遍历，点亮完整引用链路并淡出无关元素；当仅命中唯一节点时自动选中并居中放大，免去手动定位。

若 D3 未能加载，图谱分栏降级为文字版引用列表，不影响抽屉其余功能。

### 6.6 响应式与可读性

EDA 原生 API 为千级条目，若全量入图会造成严重卡顿。因此图谱默认只渲染提示词、精选工具与 MCP 元工具三类节点，原生 API 类型默认折叠，需要时在图例中手动开启。展开后节点数较多，系统依赖图例过滤与搜索聚焦来控制可读性，避免信息过载。

## 七、设计要点小结

- 本地数据化把核心 AI 驱动数据从硬编码常量转为可检索、可编辑、可版本化的数据。
- 引用检测、`@引用` 高亮跳转与关系图谱共用同一份派生数据，使删除保护与可视化天然一致，降低误删与断链风险。
- 默认不激活、零成本兼容原有运行方式，降低了用户的迁移负担。
- 日志作为只读快照与业务数据隔离，保证数据维护操作不会影响回溯能力。

## 八、已知限制

- 引用解析对提示词文本不剥离注释，文档注解中的 `@` 标签可能被误识别为引用。
- 分隔条比例不做持久化，重新打开抽屉即恢复默认布局。
- 写入采用整表覆写策略，条目规模显著增长后写入开销会线性上升。
