## 一、前期准备

### 1.1 必备硬件

- 高通410随身WiFi设备
- Windows电脑(推荐Win10/11, Linux/macOS也可但需对应调整命令)
- USB数据线(最好是原装线, 确保数据传输稳定)
- 可选: SIM卡(刷机后测试网络用)

### 1.2 必备软件与固件

> **说明**: 以下软件和固件是刷机过程中必需的, 请确保在开始前全部准备完成。

| 软件/固件 | 用途 | 获取途径 |
|----------|------|---------|
| **随身WiFi助手** | 安装驱动、ADB调试、Fastboot操作 | 刷机包内通常包含, 或搜索"酷铵水遍 随身WiFi助手", 详见[资源下载](#七资源下载与参考) |
| **ADB/Fastboot工具** | 设备调试与刷机 | 刷机包内包含, 或安装Android SDK Platform Tools, 详见[资源下载](#七资源下载与参考) |
| **高通QPST工具** | 基带备份与恢复(可选但建议) | 高通官网或第三方可靠来源 |
| **Debian固件包** | 适用于高通410的Debian系统镜像 | 搜索"苏苏小亮亮 Debian固件"或"OpenStick Debian", 详见[资源下载](#七资源下载与参考) |
| **SSH客户端** | 刷机后连接Debian系统 | FinalShell、Putty、Xshell等 |

**验证**: 检查所有文件是否下载完成, 固件包是否与设备型号匹配(如UFI001C对应UFI001C的固件)。

## 二、安装驱动与配置环境

### 2.1 安装ADB与Fastboot驱动

1. 解压下载的刷机包, 找到"驱动"文件夹或"随身WiFi助手"
2. 打开"随身WiFi助手.exe", 输入"1"回车进入驱动安装菜单
3. 再次输入"1"回车, 选择自动安装驱动(将会自动安装vivo手机驱动, 或者叫9008驱动)
4. 按照提示完成安装, 可能需要重启电脑

**验证**:
- 重启电脑后, 将随身WiFi正常插入USB口
- 打开设备管理器(Win+X+M), 查看是否有"ADB Interface"或"Android Device"设备, 无黄色感叹号
- 打开命令提示符(CMD)或PowerShell, 进入ADB工具目录, 执行:
  ```powershell
  # 列出所有已连接的ADB设备
  # 正常应显示设备序列号和"device"状态
  .\adb devices
  ```
  应显示设备序列号, 状态为"device"
  
  > **⚠️ 常见问题**: 有时候设备管理器中出现adb设备, 但是使用`adb devices`无法看到, 很可能就是'vivo手机驱动'不兼容导致的, 要把它卸载了重新插入再执行看看。

### 2.2 备份设备关键数据(可选但强烈建议)

> **⚠️ 重要提示**: 刷机前备份基带数据(IMEI等信息)非常重要, 丢失后可能导致设备无法使用移动网络。

1. 确保设备已通过ADB连接(验证步骤2.1已完成)
2. 备份基带(IMEI等重要信息):
   ```bash
   # 进入设备shell环境
   .\adb shell
   
   # 获取root权限(部分设备可能需要先获取root)
   su
   
   # 备份基带分区1(modemst1)到SD卡
   dd if=/dev/block/mmcblk0p1 of=/sdcard/modemst1.bin
   
   # 备份基带分区2(modemst2)到SD卡
   dd if=/dev/block/mmcblk0p2 of=/sdcard/modemst2.bin
   
   # 退出shell
   exit
   
   # 将备份文件从设备拉取到电脑当前目录
   .\adb pull /sdcard/modemst1.bin .
   .\adb pull /sdcard/modemst2.bin .
   ```
3. 备份当前系统(可选):
   ```bash
   # 备份整个Android系统到backup.ab文件
   .\adb backup -all -f backup.ab
   ```

**验证**: 检查备份文件是否生成, 大小是否合理(modemst1.bin/modemst2.bin通常为几MB)。

更多备份方法请参考[资源下载](#七资源下载与参考)章节中的备份教程。

## 三、进入Fastboot模式

### 3.1 方法一: ADB命令进入(推荐)

1. 确保设备已通过ADB连接(验证步骤2.1已完成)
2. 在命令行执行:
   ```bash
   # 重启设备并进入Fastboot引导加载程序模式
   .\adb reboot bootloader
   ```
3. 设备会重启并进入Fastboot模式(屏幕可能无显示, 正常现象)

**验证**:
- 执行以下命令, 应显示设备序列号, 状态为"fastboot":
  ```bash
  # 检查Fastboot模式下设备连接状态
  .\fastboot devices
  ```
- 设备管理器中应显示"Android Bootloader Interface"设备

### 3.2 方法二: 按键强制进入(ADB无法连接时使用)

1. 断开设备与电脑的连接
2. 长按设备上的复位键/功能键(通常在设备侧面或底部小孔内)
3. 保持按住按键的同时, 将设备插入电脑USB口
4. 听到电脑提示音后1-2秒松开按键

**验证**: 同方法一, 执行`fastboot devices`命令能检测到设备。

## 四、刷入Debian系统

### 4.1 解压固件包

> **⚠️ 重要**: 确保固件包与设备型号匹配, 错误的固件可能导致设备无法启动。

1. 将下载的Debian固件包(通常为debian.zip)解压到与ADB/Fastboot工具同目录下的"debian"文件夹
2. 确保解压后的文件包含以下关键文件:
   - `boot.img` - 引导分区镜像
   - `system.img` - 系统分区镜像(包含Debian系统)
   - `vendor.img` - 供应商分区镜像(包含硬件驱动)
   - `flash.bat`(Windows) 或 `flash.sh`(Linux/macOS) - 自动刷机脚本

**验证**: 检查"debian"文件夹内是否有上述关键文件, flash脚本是否可执行。

### 4.2 执行刷机脚本

> **⚠️ 注意事项**: 刷机过程中请勿断开USB连接, 否则可能导致设备变砖。

1. 确保设备已进入Fastboot模式(验证步骤3已完成)
2. 双击"debian"文件夹中的**flash.bat**(Windows), 或在Linux/macOS终端执行:
   ```bash
   # 进入固件目录
   cd debian
   
   # 为刷机脚本添加执行权限(Linux/macOS)
   chmod +x flash.sh
   
   # 执行刷机脚本
   ./flash.sh
   ```
3. 按照脚本提示操作, 通常需要多次按任意键继续, 期间设备会多次重启和重新连接
4. 等待刷机完成, 直到屏幕显示"**ALL Done!**"

**验证**:
- 刷机过程中无报错(如"FAILED"提示)
- 最终显示"ALL Done!"表示刷机成功
- 设备自动重启, 指示灯正常闪烁(通常为蓝灯或绿灯)

### 4.3 手动刷机(脚本失败时备用)

> **⚠️ 警告**: 手动刷机需要确保固件文件路径正确, 错误的刷机操作可能导致设备无法启动。

如果自动脚本失败, 可尝试手动输入以下命令(确保设备在Fastboot模式):
```bash
# 刷入引导分区(boot分区)
fastboot flash boot debian/boot.img

# 刷入系统分区(包含Debian系统文件)
fastboot flash system debian/system.img

# 刷入供应商分区(vendor分区, 包含硬件驱动)
fastboot flash vendor debian/vendor.img

# 刷入恢复分区(可选, 用于系统恢复)
fastboot flash recovery debian/recovery.img

# 清除缓存分区
fastboot erase cache

# 重启设备
fastboot reboot
```

**验证**: 每条命令执行后显示"OKAY", 无报错信息。

## 五、刷机后配置与验证

### 5.1 连接Debian系统

#### 5.1.1 通过WiFi连接

> **使用场景**: 当需要通过WiFi连接设备进行配置时使用此方法。

1. 刷机完成后, 设备会自动创建WiFi热点
   - **默认WiFi名称**: 通常为"4G-wifi"或"OpenStick"
   - **默认密码**: root/1(具体以固件说明为准)
2. 连接WiFi热点:
   - 如果进行插卡使用, 这时候就可以连接该热点使用了
   - 如果要连接家里的wifi进行上网, 则需要按照下面步骤将wifi主机模式改成从机模式(参考5.1.2节)

#### 5.1.2 通过USB网络共享连接

> **使用场景**: 当需要通过电脑USB接口连接设备并进行网络配置时使用此方法。

1. 设备插入电脑后, 会自动识别为网络适配器(基于远程NDIS的Internet共享设备), 电脑会自动获取IP地址

   > **⚠️ 驱动问题排查**: 如果USB连接电脑却无法通过USB共享上网, 任务管理器中可以识别到Android ADB Interface, 则可以尝试以下操作:
   1. 右键Android ADB Interface, 选择属性
   2. 点击驱动程序选项卡, 更新驱动程序
   3. 浏览我的电脑以查找驱动程序
   4. 让我从计算机上的可用驱动程序列表中选择
   5. 找到'网络适配器', 如果没有找到'基于远程NDIS的Internet共享设备', 则可能已经安装了别的不兼容驱动导致, 必须使设备变为未知设备后再重试(右键-卸载-删除驱动-重新插拔)
   6. 左侧厂商找到'Microsoft', 右侧找到'基于远程NDIS的Internet共享设备'
   7. 在跳出的警告对话框中选择'是'

2. 使用adb shell连接系统, 进行配网:
   ```bash
   # 连接设备shell
   .\adb shell
   ```

3. 使用界面配网工具nmtui:
   ```bash
   # 配置终端环境变量(在adb中使用nmtui必须设置, 否则无法正常显示界面)
   export TERM=linux
   
   # 启动网络管理文本用户界面
   nmtui
   ```
   > **⚠️ 重要提示**: 如果你没有使用USB+ADB的方式连接, 而是使用上面所说的自动创建的WiFi热点连接, 一删除网桥就会被踢出去, 根本没办法完成配网。

4. 在nmtui界面中操作:
   - 选择"编辑连接" → "网桥" → "删除"(删除默认网桥配置)
   - 选择"启用连接" → "WiFi" → 输入WiFi密码 → "激活"

### 5.2 SSH登录Debian系统

> **默认连接信息**: 不同固件的默认IP和密码可能不同, 请以固件说明为准。

1. 打开SSH客户端(如Putty、FinalShell、Xshell等)
2. 输入默认IP地址(通常为192.168.1.1或通过WiFi热点获取的IP)
3. 输入默认用户名和密码: **root/1**(具体以固件说明为准)
4. 点击连接, 成功登录系统

**验证**:
- 能成功登录SSH, 看到Debian系统的命令行界面
- 执行以下命令验证系统信息:
  ```bash
  # 查看系统内核信息, 应显示armv7l架构和Debian系统
  uname -a
  ```
  显示系统信息应包含"armv7l"(高通410为32位ARM架构)和"Debian"字样

### 5.3 系统基本配置(可选但推荐)

#### 5.3.1 修改默认密码

> **⚠️ 安全提示**: 修改默认密码是基本安全措施, 强烈建议立即修改。

1. 登录后执行:
   ```bash
   # 修改root用户密码
   passwd root
   ```
2. 按照提示输入新密码并确认(输入时不会显示字符, 这是正常现象)

**验证**: 退出SSH后重新登录, 使用新密码能成功登录。

#### 5.3.2 更新系统软件包

> **提示**: 首次更新可能需要较长时间, 请耐心等待。如果遇到网络问题, 可能需要配置代理或更换软件源。

1. 执行以下命令更新软件源并升级系统:
   ```bash
   # 更新软件包列表(从软件源获取最新版本信息)
   apt update
   
   # 升级所有已安装的软件包(-y参数表示自动确认, 无需交互)
   apt upgrade -y
   ```
2. 等待更新完成(首次更新可能需要较长时间)

**验证**:
- 无错误提示(如404错误表示软件源可能有问题, 需更换)
- 执行以下命令检查是否还有待升级的软件包:
  ```bash
  # 列出所有可升级的软件包, 应显示为空
  apt list --upgradable
  ```

#### 5.3.3 配置网络连接

> **使用场景**: 当需要配置移动网络(4G/5G)连接时使用此方法。

1. 配置移动网络(插入SIM卡后):
   ```bash
   # 添加GSM移动网络连接配置
   # type gsm: 连接类型为GSM移动网络
   # ifname cdc-wdm0: 使用cdc-wdm0网络接口
   # con-name mobile: 连接名称为mobile
   # apn: 接入点名称, 需要替换为你的运营商APN
   nmcli con add type gsm ifname cdc-wdm0 con-name mobile apn "你的运营商APN"
   
   # 激活移动网络连接
   nmcli con up mobile
   ```
   **常见运营商APN**:
   - 中国移动: `cmnet` 或 `cmwap`
   - 中国联通: `3gnet` 或 `3gwap`
   - 中国电信: `ctnet` 或 `ctwap`

**验证**:
- 执行以下命令测试网络连通性:
  ```bash
  # 测试网络连接, 应能收到4个响应包
  ping baidu.com -c 4
  ```
- 执行以下命令查看连接状态:
  ```bash
  # 显示所有网络连接, mobile连接状态应为"activated"
  nmcli con show
  ```



#### 5.3.4 连接扩展坞(可选)

> **使用场景**: 当需要连接USB存储设备、USB网卡、USB键盘鼠标等外设时, 需要将设备从USB从机模式切换为主机模式。

> **⚠️ 重要提示**: 
> - 切换为主机模式后, 设备将无法通过USB与电脑进行网络共享
> - 如需恢复USB网络共享功能, 执行: `echo peripheral > /sys/kernel/debug/usb/ci_hdrc.0/role`
> - 挂载前建议先使用`fdisk -l`查看设备分区信息, 确认分区格式

**操作步骤**:

1. **设置USB主机模式**:
   ```bash
   # 查看当前USB角色模式
   # 输出为"host"表示主机模式, "peripheral"表示从机模式
   cat /sys/kernel/debug/usb/ci_hdrc.0/role
   
   # 设置为主机模式(允许连接USB外设)
   echo host > /sys/kernel/debug/usb/ci_hdrc.0/role
   ```

2. **查看已连接的USB设备**:
   ```bash
   # 列出所有USB设备(包括U盘、USB网卡、USB Hub等)
   lsusb
   
   # 查看所有块设备(包括U盘、SD卡等存储设备)
   # 输出示例:
   # sda, sdb等为USB存储设备
   # mmcblk0为设备内置存储
   # zram0为虚拟内存交换分区
   lsblk
   ```

3. **挂载USB存储设备**:
   ```bash
   # 创建挂载点目录(可根据需要自定义目录名)
   mkdir -p /media/usb1
   
   # 挂载U盘第一个分区
   # 注意: 根据lsblk输出调整设备名, 如sda1, sdb1等
   # 如果设备有多个分区, 可以分别挂载sda1, sda2等
   mount /dev/sda1 /media/usb1
   
   # 查看挂载内容, 确认挂载成功
   ls /media/usb1
   ```

4. **卸载USB存储设备**(使用完毕后):
   ```bash
   # 卸载设备(确保没有程序正在使用该设备)
   umount /media/usb1
   
   # 可选: 删除挂载点目录
   rmdir /media/usb1
   ```

**验证**:
- 执行`lsusb`应显示连接的USB设备
- 执行`lsblk`应显示USB存储设备(如sda, sdb等)
- 挂载后执行`df -h`应显示挂载点及其使用情况

## 六、常见问题与解决方法

### 6.1 连接相关问题

| 问题 | 可能原因 | 解决方法 |
|-----|---------|---------|
| **ADB无法识别设备** | 驱动未正确安装或驱动冲突 | 1. 检查设备管理器中是否有黄色感叹号<br>2. 卸载不兼容的vivo手机驱动, 重新安装9008驱动<br>3. 尝试更换USB接口或USB数据线<br>4. 重启电脑后重新连接设备 |
| **Fastboot模式无法进入** | 设备未正确进入Fastboot模式 | 1. 确认ADB连接正常后执行`adb reboot bootloader`<br>2. 尝试按键强制进入(方法见3.2节)<br>3. 检查设备管理器是否显示"Android Bootloader Interface" |
| **SSH无法连接** | 网络配置错误或IP地址变化 | 1. 检查网络连接, 确认设备与电脑在同一网络<br>2. 通过随身WiFi助手查看设备IP地址<br>3. 确认SSH服务已启动: `systemctl status ssh`<br>4. 检查防火墙设置, 确保22端口未被阻止 |
| **USB网络共享无法使用** | 驱动不兼容或网络适配器未正确识别 | 1. 参考5.1.2节中的驱动问题排查步骤<br>2. 在设备管理器中手动更新驱动为"基于远程NDIS的Internet共享设备"<br>3. 卸载不兼容驱动后重新插拔设备 |

### 6.2 刷机相关问题

| 问题 | 可能原因 | 解决方法 |
|-----|---------|---------|
| **刷机脚本执行失败** | 固件文件缺失或路径错误 | 1. 检查固件包是否完整解压<br>2. 确认flash脚本与固件文件在同一目录<br>3. 尝试手动刷机(参考4.3节)<br>4. 检查设备是否在Fastboot模式 |
| **刷机后设备无法启动** | 固件不匹配或刷机过程中断 | 1. 确认固件版本与设备型号匹配<br>2. 尝试重新刷入固件<br>3. 如有备份, 尝试恢复原系统<br>4. 参考救砖教程(见7.4节) |
| **刷机后丢失IMEI/基带** | 基带分区被误刷或未备份 | 1. 如有备份, 使用QPST工具恢复基带<br>2. 参考备份教程重新写入modemst分区<br>3. 如无备份, 可能需要使用同型号设备的基带备份 |

### 6.3 系统配置问题

| 问题 | 可能原因 | 解决方法 |
|-----|---------|---------|
| **apt update失败(404错误)** | 软件源配置错误或网络问题 | 1. 检查网络连接是否正常<br>2. 更换软件源镜像(如使用清华、阿里云镜像)<br>3. 检查`/etc/apt/sources.list`文件配置是否正确 |
| **移动网络无法连接** | APN配置错误或SIM卡问题 | 1. 确认APN配置正确(参考5.3.3节)<br>2. 检查SIM卡是否正常插入<br>3. 执行`nmcli con show`查看连接状态<br>4. 查看系统日志: `journalctl -u NetworkManager` |
| **USB设备无法识别** | USB未切换为主机模式 | 1. 执行`cat /sys/kernel/debug/usb/ci_hdrc.0/role`查看当前模式<br>2. 如为peripheral模式, 执行`echo host > /sys/kernel/debug/usb/ci_hdrc.0/role`切换<br>3. 参考5.3.4节详细步骤 |

### 6.4 其他问题

| 问题 | 可能原因 | 解决方法 |
|-----|---------|---------|
| **设备发热严重** | 系统负载过高或散热不良 | 1. 检查系统负载: `top`或`htop`<br>2. 关闭不必要的服务<br>3. 确保设备通风良好, 避免长时间高负载运行 |
| **WiFi热点无法创建** | 网络配置冲突 | 1. 检查网络接口状态: `ip a`<br>2. 删除冲突的网络配置: `nmcli con delete <连接名>`<br>3. 重新配置WiFi热点 |
| **系统时间不正确** | 时区配置错误 | 1. 设置时区: `timedatectl set-timezone Asia/Shanghai`<br>2. 同步网络时间: `ntpdate -s time.nist.gov` |

> **⚠️ 提示**: 如遇到其他问题或上述方法无法解决, 请参考[资源下载](#七资源下载与参考)章节中的救砖教程和社区资源。

## 八、最终验证

> **验证目的**: 确保刷机成功, 系统运行正常, 各项功能可用。

完成所有步骤后, 执行以下命令进行最终验证:

```bash
# 1. 确认系统为Debian, 架构为armv7l
# 输出应包含: Linux、armv7l、Debian等关键字
uname -a

# 2. 确认网络接口已获取IP地址
# 检查所有网络接口状态, 确认已分配IP地址
ip a

# 3. 确认网络连接正常
# 测试外网连通性, 应能收到4个响应包
ping 8.8.8.8 -c 4

# 4. 确认软件源正常
# 更新软件包列表, 应无404等错误
apt update

# 5. 确认USB设备识别正常(如果连接了USB外设)
# 列出所有USB设备, 应显示已连接的USB外设
lsusb

# 6. 确认系统服务运行正常
# 检查关键服务状态(SSH、网络管理等)
systemctl status ssh
systemctl status NetworkManager

# 7. 确认磁盘空间充足
# 查看磁盘使用情况, 确保有足够空间
df -h
```

**验证标准**:
- ✅ 系统信息显示为Debian armv7l架构
- ✅ 网络接口已获取IP地址且能正常通信
- ✅ 软件源更新无错误
- ✅ 关键系统服务运行正常
- ✅ 磁盘空间充足(建议剩余空间>500MB)

> **🎉 恭喜**: 如果所有验证项都通过, 说明刷机成功, 可以开始正常使用Debian系统了!
